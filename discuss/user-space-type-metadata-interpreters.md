# User-space TypeMetadata interpreters

- Stage: Discussion
- Scope: user-defined interpreters with near-native logical capability
- First vertical slice: equality
- Related: `type-directed-capability-factories.md`, RFC 0055, RFC 0085

## Objective

Forma should let ordinary Forma code interpret canonical TypeMetadata with the
same public logical reach as a native interpreter. Native code may retain heap,
cache, and execution optimizations, but it should not be the only place where
users can define nested type-directed semantics.

The target is not dynamic code generation:

```text
TypeOf(A) -> generated bytecode specialized for A
```

It is user-space data interpretation with a typed outer boundary:

```text
TypeOf(A) + user interpreter + values of A
    -> deterministic interpreted result
```

Equality is the first vertical slice because its result type is fixed, Forma
already has an authoritative native behavior for conformance, and it exercises
every logical value shape without requiring dynamic reconstruction.

## Existing foundation

Runtime TypeMetadata is already canonical data. Its nodes are Dict values with
fields including:

```text
kind
item
items
fields
variants
parameters
result
attributes
inner
```

`TypeOf(A)` adds the static witness that a metadata value describes `A`; it is
not a second runtime representation. Attribute helpers already normalize,
strip, enumerate, and query `WithAttributes` wrappers. Dict helpers already
enumerate arbitrary Dict values as keys, values, or pairs.

The missing foundation is primarily safe logical observation of arbitrary
runtime values, public handling of recursive metadata references, and complete
`TypeOf(A)` witness inference through higher-order factory results.

## Semantic parity, not implementation parity

A Forma interpreter and a native interpreter should have equal access to:

- every public TypeMetadata node;
- every public logical Value kind;
- Struct/Dict fields, Array/Tuple items, and Tagged tag/payload;
- normalized attributes;
- recursive descent through TypeMetadata;
- nested user overrides;
- structured `BlameError` values and stable paths;
- fallback composition; and
- deterministic fuel, quota, cancellation, and publication behavior.

Native implementations may exclusively retain:

- raw heap handles and object layout;
- hidden up-link representation;
- internal visited-set storage;
- persistent plan caches and interning;
- bulk heap access and specialized execution; and
- future bytecode or JIT optimization.

For every retained privilege, the public interpreter ABI must provide a safe
logical equivalent or an explicit fallback. Silent loss of a node through
`Any` is not an acceptable boundary.

## Open recursion

A user interpreter must be able to override nested semantics. Calling a native
fallback only at the root is insufficient: a custom field attribute would be
ignored as soon as traversal entered the fallback.

The proposed model is open recursion. An interpreter receives a context whose
`recur` operation re-enters the complete dispatcher:

```forma
@struct type EqContext = {
    path: String,
    recur: Fn(
        String,
        Type,
        Any,
        Any,
    ) -> Result(Bool, BlameError),
    fallback: Fn(
        String,
        Type,
        Any,
        Any,
    ) -> Result(Bool, BlameError),
};
```

The provisional user interpreter shape is:

```forma
Fn(
    EqContext,
    Type,
    Any,
    Any,
) -> Result(Bool, BlameError)
```

This is an operation-specific dynamic ABI, not a universal interpreter type.
It is ordinary rank-1 data: `recur` and `fallback` are monomorphic Functions
over `Type` and `Any`.

Conceptually:

```text
dispatch(path, type, left, right)
    resolve current recursive metadata reference
    check cancellation, fuel, and visited pair
    construct context
    call user interpreter(context, type, left, right)

context.recur(segment, child_type, child_left, child_right)
    dispatch(path + segment, child_type, child_left, child_right)

context.fallback(segment, type, left, right)
    call the next configured interpreter at path + segment
```

The exact `EqContext` representation remains provisional. A native closure may
be the safe capability that owns dispatcher state; no raw state token or heap
identity appears in Forma.

## Direct execution before returned closures

The lowest-risk initial native boundary directly executes one comparison:

```forma
native equal_with: for(A) Fn(
    TypeOf(A),
    EqInterpreter,
    A,
    A,
) -> Result(Bool, BlameError);
```

Ordinary Forma code can create the convenient capability:

```forma
def eq_fn: for(A) Fn(
    TypeOf(A),
    EqInterpreter,
) -> Fn(A, A) -> Result(Bool, BlameError) =
    fn(ty, interpreter) {
        fn(left, right) {
            equal_with[A](ty, interpreter, left, right)
        }
    };
```

This avoids requiring a native factory to manufacture a captured closure. The
returned closure is ordinary Forma code; the native boundary owns only one
dispatcher invocation and its traversal state.

The explicit `[A]` is currently significant. A local probe confirms that the
adapter checks and executes with `eq_fn[Int](Int)`, while `eq_fn(Int)` fails to
solve the returned Function's `A`. Closing that RFC 0055 inference gap is a
prerequisite for the intended ergonomic form.

## Fallback

Fallback is an explicit semantic operation, not recovery to `Any`.

The initial context model lets an interpreter delegate locally:

```forma
def acme_eq = fn(ctx, ty, left, right) {
    if attributes.has(ty, "acme:ignore") {
        'Ok('True)
    } else {
        ctx.fallback("", ty, left, right)
    }
};
```

Possible fallback layers include:

```text
project interpreter
    -> standard Forma reference interpreter
        -> native opaque-value interpreter
            -> Unsupported BlameError
```

An alternative `Option(Result(...))` decision protocol may make interpreter
chains easier to construct, but the first design should choose one mechanism.
Local `ctx.fallback` is provisionally preferred because the decision to
delegate often occurs after inspecting attributes and node shape.

Fallback must preserve nested overrides. When a fallback descends into a child,
that child must return through the complete dispatcher rather than remain
inside a native-only traversal.

## Opaque values

Some values have public behavior but no safe structural view. Functions and
native capabilities are the immediate examples. A user interpreter must be
able to choose among:

- delegate to authoritative opaque equality;
- treat the value as unsupported; or
- apply another public atomic operation.

Raw function or heap identity is not exposed. Native equality may compare
opaque identity through fallback, but the result is the only public fact.

Future external handles require the same explicit classification.

## Recursive types and cyclic values

Recursive TypeMetadata currently contains hidden VM up-links. These are private
representation and must not become a public Value kind. Before invoking user
code, the dispatcher should resolve the current metadata reference to a normal
logical node. Child references may remain opaque until passed back to `recur`,
where the dispatcher resolves them again.

Recursive type and cyclic runtime value are separate concerns:

- a recursive type over a finite tree value terminates by following the value;
- a cyclic value requires an operation-specific visited policy.

For equality, the dispatcher can own visited pairs. Other operations may need
different policies: rendering may emit a reference marker, stable hashing may
reject cycles, and encoding may return `BlameError`. A generic traversal layer
must not silently impose equality's cycle rule on every interpreter.

## Minimal logical Value observer

The first slice needs safe, read-only observation only:

```forma
value.kind: Fn(Any) -> ValueKind;
value.field: Fn(Any, String) -> Result(Any, BlameError);
value.array_items: Fn(Any) -> Result(Array(Any), BlameError);
value.tuple_items: Fn(Any) -> Result(Array(Any), BlameError);
value.tag: Fn(Any) -> Result(String, BlameError);
value.payload: Fn(Any) -> Result(Option(Any), BlameError);
```

The public `ValueKind` covers logical values only:

```text
Int Float String Bytes Dict Array Atom Tagged Tuple Function
```

It does not expose up-links, storage generations, handles, shapes, or registers.

Existing Dict enumeration is useful but insufficient as the complete observer:
it lacks dynamic `get`, and wrong-kind access raises a VM error rather than
returning a composable `BlameError`. Tuple and Tagged have no dynamic observer
today. Union and `Any` interpretation need `value.kind` to select a logical
branch or explain a mismatch.

Dynamic construction, mutation, heap identity, and graph reconstruction are
outside the equality slice. They are required by user-defined transformers and
must be designed separately after observer semantics are proven.

## Error and resource boundary

Logical interpretation failures are values:

```text
wrong logical kind
missing field
unknown variant
unsupported opaque node
policy rejected by attributes
```

They return `BlameError` with data, rule, message, and a dispatcher-owned path.

Interpreter execution failures remain VM/query failures:

```text
fuel exhausted
allocation quota exhausted
call depth exhausted
cancelled query
stale revision
trusted native bug
```

The dispatcher and callback continuations must use the existing shared quota
and cancellation checkpoints. Cancellation or stale revision publishes no
partial result or cached traversal state.

## Current gap audit

### Already available

- canonical TypeMetadata for primitive, Array, Dict, Tuple, Struct, Enum,
  Union, Function, Atom, Tagged, attributed, and named types;
- `TypeOf(A)` witnesses and explicit type application;
- normalized attribute wrappers and attribute access helpers;
- arbitrary Dict key/value/pair enumeration and Dict construction;
- generic Array traversal combinators;
- ordinary recursive Forma definitions with explicit contracts;
- typed higher-order adapters when the type argument is explicit;
- shared fuel, allocation, call-depth, cancellation, and publication machinery;
- structural native equality as a conformance reference.

### Missing or incomplete

1. `TypeOf(A)` evidence does not currently infer `A` through the tested
   higher-order `eq_fn(Int)` result; explicit `eq_fn[Int](Int)` works.
2. Hidden recursive metadata up-links have no public logical resolution path.
3. Dynamic Dict lookup lacks a safe Result-returning API.
4. Array access through `Any` reports wrong-kind failures as VM errors rather
   than interpreter blame.
5. Tuple has no dynamic item observer.
6. Tagged/Enum values have no dynamic tag and payload observer.
7. There is no public logical runtime `ValueKind`.
8. Union selection cannot be implemented robustly without logical kind and
   validation helpers.
9. User interpreters cannot maintain visited sets or memoized plan state.
10. Existing dynamic access errors do not uniformly carry a dispatcher-owned
    blame path.
11. TypeMetadata's recursive-reference and malformed-node behavior is not yet
    a complete public interpreter ABI.
12. User-defined transformers need dynamic construction plus validation back
    into `A`; equality deliberately avoids that larger problem.

## Native and Forma conformance

The equality slice is complete only when a Forma reference interpreter and a
native optimized interpreter pass the same logical suite:

| Case | Native | Forma |
| --- | --- | --- |
| scalar | same Bool | same Bool |
| Array/Dict | same result/path | same result/path |
| Tuple/Struct | same result/path | same result/path |
| Atom/Tagged/Enum | same result/path | same result/path |
| Union | same selection/error | same selection/error |
| attributes | same policy | same policy |
| recursive type | terminates | terminates |
| cyclic value | same policy | same policy |
| opaque Function | same fallback result | same fallback result |
| malformed value | same blame category/path | same blame category/path |
| cancellation | atomic | atomic |
| quotas | bounded | bounded |

Native may be faster and may cache plans. It may not recognize a public logical
case that the Forma interpreter ABI cannot observe or delegate.

## Staged validation plan

Before a numbered RFC series:

1. fix or isolate the `TypeOf(A)` higher-order witness-inference gap;
2. prototype the minimal read-only Value observer;
3. define logical recursive metadata resolution without exposing up-links;
4. implement a non-cyclic Forma equality interpreter;
5. implement direct `equal_with` dispatch and open recursion;
6. add visited-pair handling for cyclic equality;
7. implement one nested attribute override;
8. compare a Forma reference interpreter with native structural equality;
9. classify every divergence as missing observation, deliberate native
   privilege, or incorrect semantics; and
10. only then extract an umbrella RFC and independently executable child RFCs.

The first RFC series, if justified, should remain equality-specific. A second
operation such as stable hashing or rendering must validate any proposed
general interpreter abstraction before that abstraction becomes language or
standard-library policy.

## Success boundary

The experiment succeeds when ordinary Forma code can define equality semantics
for every public nested logical type, override behavior through metadata
attributes, recur through the common dispatcher, and explicitly delegate
opaque or unsupported nodes. Native code may improve representation and speed,
but not public logical reach.

It fails if meaningful nested behavior remains available only to code that can
inspect VM internals and no safe recurse/fallback API can close that gap. That
failure should narrow the user-interpreter claim rather than motivate exposure
of raw heap state.
